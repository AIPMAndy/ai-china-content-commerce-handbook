## 22条攻击清单

- [x] 01 只靠热点没商品需求 → 真实评论需求表。
- [x] 02 AI虚构商品效果 → 事实卡逐句核验。
- [x] 03 图片生成掩盖商品缺陷 → 实拍原片必存。
- [x] 04 所有平台一起做 → 单平台验证原则。
- [x] 05 买手没有带货资格 → 阻塞与服务商替代。
- [x] 06 把GMV当税后利润 → 单笔经济模型与字段口径。
- [x] 07 退款后仍付快递 → 原订单计正向物流。
- [x] 08 退款货不能再卖 → 单笔退货损耗说明。
- [x] 09 佣金按订单付款时算 → 退款后结佣模型。
- [x] 10 佣金/平台费实际口径不同 → 所有费率为实际核验输入。
- [x] 11 单个爆款推导出稳定收入 → 7天与30天分批测试。
- [x] 12 匿名商家的不可核查数字 → 单独标记来源等级。
- [x] 13 AI使用与增长因果混同 → AI归因字段。
- [x] 14 服务商利润没算人工 → 工时人工成本输入。
- [x] 15 高客单品牌案例不适用新手 → 最小动作复刻，不抄预算。
- [x] 16 直播身份与授权不合规 → 官方入口/法规链接。
- [x] 17 隐去AI标识 → 标识记录与法条链接。
- [x] 18 客户隐私上传模型 → AI输入脱敏。
- [x] 19 带货关联功能突然调整 → 不硬编码门槛/费用。
- [x] 20 网站断网打不开数据 → 预置本地 JS 数据。
- [x] 21 用户在手机上页面过窄 → CSS 960/640/390断点。
- [x] 22 只有文字没交付物 → 14 CSV、30章验收、26 Prompt、打卡与导出。

## 仍待线上验收

- GitHub 新仓库尚未建立，尚未做 GitHub Pages 线上部署与 Actions 结果核验。
- 登录态/地区/类目特有的开店页面需要读者在自己的合法商家后台核对。
- 案例GMV没有独立财务审计。即使平台官方披露，也不能包装为净利润。
- 是否打开具体平台 App 的全部菜单、是否有账户权限，不能从公共网页确认。

## 发行门槛

- 所有案例有来源URL和业绩口径；未知 AI 归因不冒充 AI 案例。
- 30章都含动作/验收/失败处理；30天都含明确证据。
- 计算器校验负数/百分比越界/退款100%等边界。
- 生成网页无外部 JS / CSS 依赖，关键页链接存在。
- GitHub Actions 在新仓库内执行相同检查后才能宣称线上通过。
