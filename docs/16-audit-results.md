# 第三轮对抗式审核｜证据、财务、交互、上线

审核基准：2026-11-05。审核分为“脚本可验证”和“还需真人真实经营验证”，不能把自动测试通过说成已经跑通销售。

## 第一轮：财务反方（高严重度）

1. 拿GMV当利润 → 单独输出GMV、扣退款收入、变动成本、贡献利润、固定投入之后的净贡献。
2. 退款不算成本 → 退款后保留订单数和物流/退货损耗均参与计算。
3. 达人按广告曝光算佣金 → 只按假定的净成交GMV结算；实际仍需核对平台佣金结算。
4. B端只计服务费 → 计入客户数量、交付小时、时薪、外包、工具与获客。
5. 高退款无止损 → 现场算退款翻倍和广告上涨情境。
6. 缺陷仍待验证：税款、资金占用、实际退货后的货损、批量广告归因和平台订单状态未完全建模。模板留出扩展字段。

## 第二轮：事实与平台反方（高严重度）

1. 37个案例都记录原始来源和结果口径。
2. 将“未披露AI”与“AI参与但没验证因果”明确分开。
3. 匿名商家和大促商家的可复制性降低，适合作为打法线索，不作为净利润样本。
4. 2025-09-01 AI标识规定、2026-02-01 直播电商监督办法放在开播核验清单。
5. 每个平台只列官方学习中心/后台入口，不凭空填写可能过期的门槛、保证金和佣金率。
6. 缺陷仍待验证：原始链接是否长期有效、平台登录后页面内容、每个案例成本和净利润、每条平台规则当前页面。务必人工复核。

## 第三轮：新手、技术与交付反方

1. 新手没有店铺/货源 → 有达人真实试用、服务商诊断、实体老客等替代路径；无法挂商品标记阻塞。
2. 没有“第一个动作” → 40分钟任务、7天首单演练、30天逐日证据。
3. 课程像目录、没有可执行产出 → 每章三步、验收标准、失败替代。
4. 用户不想装软件 → 浏览器直接打开`site/index.html`，离线使用。
5. 信息堆叠难导航 → 课程、案例、Prompt、路径筛选，另有单章页可收藏。
6. 外包商夸大服务效果 → 4周试点交付范围和“不保证成交额”的双方依赖表。
7. GitHub部署后首页空白 → 数据以静态`data.js`加载，无网络数据依赖；生成独立章节/案例页。
8. 真实客户数据被泄露 → CSV存本机，工作日志被gitignore排除；不上传账号或订单原始隐私。

### 报告使用边界

自动化只验证数据结构、成本计算和静态资源的可用性；不证明案例原始业绩，也不代表真实发布或真实成交。每次补数据后重新运行并更新结果。真实首单必须以平台后台付款记录与扣退款的结算凭证为准。
